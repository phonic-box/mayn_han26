# May'n ひらがな はんぐじゃむ 披露楽曲管理ツール

今回のツアーで「どの曲が歌われたか／まだ歌われていないか」を仲間内で共有するための、スマホ向け Web アプリです。
Google Apps Script（HTML Service）と Google スプレッドシートだけで動き、外部サーバーやビルドは不要です。

- 管理者がスプレッドシートにセットリストを登録し、仲間は Web アプリで見るだけ
- 公演を選ぶと、その公演のセットリストを曲順で表示
- 全公演では、ツアー全体で披露済み／未披露の曲と、歌われた公演名を表示（セットリストから都度算出）
- 曲名・読みの先頭一致で検索、読みの 50 音順で表示

> 同梱のダミーデータ（`楽曲A`、`東京公演（サンプル）` など）は動作確認用です。`data/` には今回のツアーの公演一覧と楽曲一覧を置いています。

## ファイル構成

```text
src/                 ← Apps Script プロジェクトに入れるファイル
├── Code.gs          シート読み込み・セットリスト照合、シート初期化・移行（管理者用）
├── Index.html       画面
├── Styles.html      CSS
├── Logic.html       表示判定（並び順・検索・披露判定）の純粋関数
├── Scripts.html     画面の動作
└── appsscript.json  マニフェスト（clasp を使う場合）
data/                ← シートに貼る初期データ（タブ区切り）
├── shows.tsv        対象 19 公演（東京 2 日目・神奈川はリクエスト対象外のため除外）
└── songs.tsv        楽曲 212 曲（読みは空）
test/                ← ローカルテスト（Node.js、依存なし）
dev/                 ← プレビュー生成、手で貼る用の 2 ファイル生成
```

## データ（スプレッドシート）

3 シートを使います。1 行目はヘッダー（列名で読むので列順は自由、余計な列があっても可）。

### `Songs`（楽曲一覧）

| song_id | title | reading |
|---|---|---|
| M0001 | May’n☆Space | |
| S002 | 楽曲B | がっきょくびー |

- `song_id` は一度決めたら変えない・使い回さない。
- `reading` は任意（ひらがな推奨）。入れると 50 音順の位置と、ひらがなでの検索に効く。空なら曲名で並ぶ。
- **`Songs` に無い曲は全公演の一覧に出ません。** 未披露確認に使うなら網羅的に登録してください。

### `Shows`（公演一覧）

| show_id | show_name | show_date | venue | sort_order |
|---|---|---|---|---|
| P001 | 東京 1回目 | 2026-10-20 | 東京キネマ倶楽部 | 1 |
| P002 | 東京 2回目 | 2026-10-20 | 東京キネマ倶楽部 | 2 |

- 同じ日の 1 回目・2 回目、同じ都市の別日は別の公演にする。`show_name` も重ならないようにする（Setlists で名前を使うため）。
- プルダウンは `sort_order` の小さい順。`show_date` は任意（入っていればプルダウンに併記）。

### `Setlists`（セットリスト）

| show | no | title |
|---|---|---|
| 東京 1回目 | 1 | May’n☆Space |
| 東京 1回目 | 2 | ダイアモンド クレバス |

- 1 行が 1 曲。`show` と `title` はプルダウンから選べる（`setupSheets` で入力規則を設定）。
- `show` は `show_name`（または `show_id`）、`title` は `Songs` の曲名（または `song_id`）と一致させる。
- 画面では `no` の小さい順に並ぶ。`no` が空の行は最後に、入力した順で並ぶ。
- 同じ公演で同じ曲を 2 回歌った場合は 2 行入れてよい。
- 照合できない行（公演名・曲名の打ち間違いなど）は、画面上部に「シートに確認が必要な行があります」と行番号付きで出る。

## セットアップ

### 1. スプレッドシートと Apps Script を作る

1. Google スプレッドシートを新規作成する（名前は自由）。
2. メニュー **拡張機能 → Apps Script** を開く。
3. コードを貼り付ける。`npm run bundle` で生成される 2 ファイルを貼るのが簡単。
   - 既存の `コード.gs` の中身を全部消し、`dist/gas/Code.gs` の中身を貼る。
   - **＋ → HTML** で `Index` を作り（拡張子 `.html` は自動で付く）、`dist/gas/Index.html` の中身を貼る。
   - （`src/` の 5 ファイルをそれぞれ同じ名前で作って貼っても同じように動く）
   - タイムゾーンは **プロジェクトの設定** で `Asia/Tokyo` にしておく。
4. 保存する。

<details>
<summary>clasp を使う場合</summary>

```sh
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を Apps Script の「プロジェクトの設定」から貼る
clasp push
```

</details>

### 2. シートを初期化する

Apps Script エディタで関数 `setupSheets` を選んで **実行**（初回は権限の承認が必要）。

- `Songs` / `Shows` / `Setlists` シートがヘッダー付きで作られる。新規作成時だけダミーデータが入る。既にデータがあるシートは変更しない。
- `Setlists` の `show` / `title` 列にプルダウンを設定する。

スプレッドシートを開き直すと、メニュー **楽曲管理** からも実行できます。

### 3. Web アプリとしてデプロイする

1. エディタ右上の **デプロイ → 新しいデプロイ**。
2. 種類の選択で **ウェブアプリ**。
3. 設定:
   - **次のユーザーとして実行**: `自分`
   - **アクセスできるユーザー**: 下の「公開範囲」を参照
4. **デプロイ** を押し、表示された URL（`.../exec`）を仲間に共有する。

コードを更新したら **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン** で同じ URL のまま反映できます（「新しいデプロイ」だと URL が変わる）。シートの中身の変更はデプロイ不要で、画面の ↻ で反映されます。

### 公開範囲

Web アプリは閲覧専用で、画面からデータを書き換える関数は公開していません。スプレッドシート自体を仲間に共有する必要もありません。

| アクセスできるユーザー | 誰が見られるか | 注意 |
|---|---|---|
| `全員` | ログイン不要で誰でも | URL を知っていれば誰でも閲覧できる。LINE などのアプリ内ブラウザでもそのまま開ける |
| `Google アカウントを持つ全員`（`appsscript.json` の既定） | Google にログインしている人 | アプリ内ブラウザや複数アカウントのログイン状態では開けないことがある |

- 見られるのは曲名・公演・セットリストだけです。URL は仲間内でだけ共有してください。

## 運用（管理者）

### 公演が終わったら

1. `Setlists` の最終行の下に、その公演の曲を 1 曲 1 行で入れる（`show` と `title` はプルダウン、`no` は曲順）。
2. 画面の ↻ で反映を確認する。画面上部に警告が出たら、示された行を直す。

確認できたセットリストだけを登録し、推測では入れないでください。

### 楽曲・公演を追加する

- **楽曲**: `Songs` の最終行の下に `song_id` / `title` / `reading` を 1 行足す。`song_id` は既存と重ならない続き番号に。
- **公演**: `Shows` に 1 行足す（`show_id` と `show_name` は重ならないように、`sort_order` で並び順を指定）。
- 追加した曲・公演が `Setlists` のプルダウンに出ない場合は、`setupSheets` をもう一度実行する（プルダウンの範囲を更新する。データは変えない）。
- 曲名が `1/2` のように日付や数値と解釈されそうな場合は、セルの書式を **表示形式 → 数字 → 書式なしテキスト** にしてから入力する。
- 曲名・公演名を変えるときは、`Setlists` 側の同じ名前も直す（`song_id` / `show_id` で書いた行は直さなくてよい）。

### 旧バージョン（画面でチェックしていた版）からの移行

1. 新しいコードを貼ってデプロイし直す。
2. Apps Script で `migrateChecksToSetlists` を実行する（メニュー **楽曲管理 → 旧チェックを Setlists に移す** でも可）。
   - `Songs` の `performed_show_ids` 列にあるチェックを、公演ごとに `Setlists` へ書き出す。チェックには曲順が無いので `no` は空欄になる。
   - 1 回だけ動く（2 回目以降は何もしない）。既に `Setlists` にある公演・曲の組み合わせは重複させない。
3. `Setlists` で `no` を入れて曲順を整える。
4. 確認できたら `Songs` の `performed_show_ids` 列は削除してよい（残っていても無視される）。

## 使い方（仲間）

- **全公演**: ツアー全体の一覧。**披露済み** はどこかの公演で歌われた曲と公演名、**未披露** はまだどこでも歌われていない曲（リクエスト曲選びに）。最初は「披露済み」で開く。
- **各公演**: その公演のセットリストを曲順で表示。
- **検索**: 曲名・読みの先頭一致。全角半角・大文字小文字・ひらがなカタカナ・`'` と `’` の違いは区別しない。
- **↻**: 最新のデータを読み込む（アプリに戻ってきたときは 1 分以上経っていれば自動で読み直す）。

## 開発

Node.js 18 以上があれば、追加インストールなしで動きます。

```sh
npm test          # Code.gs と表示ロジックのテスト
npm run preview   # http://localhost:8765/preview.html で画面を確認
npm run bundle    # 手で貼る用の dist/gas/Code.gs と dist/gas/Index.html を生成
```

プレビューは Code.gs をブラウザ内のモックで動かすもので、データはリロードで初期化されます。
`?fail=1` で読み込み失敗、`?delay=2000` で遅い通信を再現できます。
