# May'n ひらがな はんぐじゃむ 披露楽曲管理ツール

今回のツアーで「どの曲が歌われたか／まだ歌われていないか」を仲間内で共有するための、スマホ向け Web アプリです。
Google Apps Script（HTML Service）と Google スプレッドシートだけで動き、外部サーバーやビルドは不要です。

- 公演をプルダウンで選び、その公演で歌われた曲にチェックを付ける
- 1 曲を複数公演に記録でき、片方のチェックを外しても他公演の記録は残る
- ツアー全体の披露済み／未披露は保存データから都度算出（シートには保存しない）
- 曲名・読みで検索、読みの 50 音順で表示
- 楽曲・公演の追加や修正は、管理者がスプレッドシートで直接行う（画面からは記録のチェックだけ）

> 同梱のデータ（`楽曲A`、`東京公演（サンプル）` など）はすべて動作確認用のダミーです。実際の公演・セットリストは公式情報で確認してから登録してください。

## ファイル構成

```text
src/                 ← Apps Script プロジェクトに入れるファイル
├── Code.gs          データ取得・更新・検証・排他制御、シート初期化
├── Index.html       画面
├── Styles.html      CSS
├── Logic.html       表示判定（並び順・検索・披露判定）の純粋関数
├── Scripts.html     画面の動作
└── appsscript.json  マニフェスト（clasp を使う場合）
test/                ← ローカルテスト（Node.js、依存なし）
dev/build-preview.js ← GAS なしで画面を試すプレビュー生成
```

## データ（スプレッドシート）

永続データは 2 シートだけです。1 行目はヘッダー（列名で読むので列順は自由、余計な列があっても可）。

### `Songs`

| song_id | title | reading | performed_show_ids |
|---|---|---|---|
| S001 | 楽曲A | がっきょくえー | `["P001","P003"]` |
| S002 | 楽曲B | がっきょくびー | `[]` |

- `performed_show_ids` は JSON 配列の文字列。未披露は `[]`（空セルも `[]` 扱い）。
- `song_id` は一度決めたら変えない。
- `reading` はひらがな推奨（カタカナでも可）。空なら曲名で並ぶ。

### `Shows`

| show_id | show_name | show_date | venue | sort_order |
|---|---|---|---|---|
| P001 | 東京公演 | 2026-11-01 | ○○ホール | 1 |
| P002 | 東京公演 2日目 | 2026-11-02 | ○○ホール | 2 |

- 同じ都市でも別日・昼夜は別の `show_id` にする。
- プルダウンは `sort_order` の小さい順。
- `show_date` は任意（`YYYY-MM-DD` 推奨）。入っていればプルダウンに併記される。

## セットアップ

### 1. スプレッドシートと Apps Script を作る

1. Google スプレッドシートを新規作成する（名前は自由）。
2. メニュー **拡張機能 → Apps Script** を開く。
3. コードを貼り付ける。`npm run bundle` で生成される 2 ファイルを貼るのが簡単。
   - 既存の `コード.gs` の中身を全部消し、`dist/gas/Code.gs` の中身を貼る。
   - **＋ → HTML** で `Index` を作り（拡張子 `.html` は自動で付く）、`dist/gas/Index.html` の中身を貼る。
   - （`src/` の 5 ファイルをそれぞれ同じ名前で作って貼っても同じように動く）
   - タイムゾーンは **プロジェクトの設定** で `Asia/Tokyo` にしておく。
4. 保存する。

<details>
<summary>clasp を使う場合</summary>

```sh
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を Apps Script の「プロジェクトの設定」から貼る
clasp push
```

</details>

### 2. シートを初期化する

Apps Script エディタで関数 `setupSheets` を選んで **実行**（初回は権限の承認が必要）。
`Songs` / `Shows` シートがヘッダーとダミーデータ付きで作られます。既にデータがあるシートは変更しません。

スプレッドシートを開き直すと、メニューに **楽曲管理 → シートを初期化** も出ます。

### 3. Web アプリとしてデプロイする

1. エディタ右上の **デプロイ → 新しいデプロイ**。
2. 種類の選択で **ウェブアプリ**。
3. 設定:
   - **次のユーザーとして実行**: `自分`
   - **アクセスできるユーザー**: 下の「公開範囲」を参照
4. **デプロイ** を押し、表示された URL（`.../exec`）を仲間に共有する。

コードを更新したら **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン** で同じ URL のまま反映できます。

### 公開範囲（公開前に必ず決める）

「次のユーザーとして実行: 自分」なので、スプレッドシートの共有設定に関係なく、**Web アプリを開ける人は全員、披露記録（チェック）を編集できます。楽曲・公演は増やせません**（スプレッドシート自体を仲間に共有する必要はありません）。

| アクセスできるユーザー | 誰が使えるか | 注意 |
|---|---|---|
| `Google アカウントを持つ全員`（推奨・`appsscript.json` の既定） | Google にログインしている人 | URL を知っていればログイン済みの第三者も編集できる |
| `全員` | ログイン不要で誰でも | URL が漏れると誰でも改変できる。おすすめしない |
| `自分のみ` / 組織内のみ | 限られた人 | 仲間が同じ Workspace 組織にいる場合のみ現実的 |

- URL は SNS など公開の場に貼らないでください。
- 万一荒らされた場合は、スプレッドシートの **ファイル → 変更履歴** から戻せます。
- 本番データを入れる前に、ダミーデータのまま仲間のスマホで開けるか確認してください。

## 初期データの投入

1. `Shows` にダミー行を消してから、公式情報で確認した全公演を登録する（別日・別公演は別 ID）。
2. `Songs` にダミー行を消してから、対象楽曲を登録する。`performed_show_ids` はすべて `[]`。
   - 曲名の表記、別バージョン・カバー・メドレーの扱いは先に仲間内で決めておく。
   - **`Songs` に無い曲は検索にも未披露一覧にも出ません。** 未披露確認をしたいなら網羅的に登録してください。
3. 既に開催済みの公演があれば、**確認できた**披露曲だけ画面から記録する（推測で記録しない）。

シートを直接編集するときは、`performed_show_ids` を `["P001","P002"]` の形（ダブルクォート）で書いてください。壊れた値の曲は画面に「⚠ データ破損」と表示され、上書きされないよう更新を拒否します。

## 使い方

- **全公演**: 全曲を表示。どこかの公演で歌われた曲は「披露済み」と公演名が出る（閲覧のみ）。
  下の **未披露** ボタンで、どの公演でもまだ歌われていない曲だけにできる（リクエスト曲選びに）。
- **各公演**: チェックで披露を記録。チェックの変更は即保存され、「保存中…」が消えたら確定です。保存に失敗するとチェックは元に戻り、赤いメッセージが出ます。
- **披露済み / 未披露**: 選択中の対象（各公演 or 全公演ならツアー全体）で絞り込み。全公演は「披露済み」、各公演は「未披露」で始まる（全曲をまとめて出す表示はない）。
- **↻**: 他の人の更新を取り込む（アプリに戻ってきたときは 1 分以上経っていれば自動で読み直す）。

## 楽曲・公演の追加（管理者のみ）

画面から楽曲を追加する機能はありません。追加したい曲があれば管理者に伝えてもらい、スプレッドシートに直接書き込みます。
Web アプリを開ける人でも、スプレッドシートの編集権限がなければ楽曲は増やせません。

**楽曲を追加する**: `Songs` の最終行の下に 1 行足す。

| 列 | 書き方 |
|---|---|
| `song_id` | 既存と重ならない ID。続き番号（`S007` の次は `S008`）が無難 |
| `title` | 曲名。表記は仲間内で決めたものに合わせる（重複していないか検索してから） |
| `reading` | 読み（ひらがな推奨）。50 音順と検索に使う。空でも可 |
| `performed_show_ids` | `[]`（空欄でも未披露として扱う） |

**公演を追加する**: `Shows` に 1 行足す（`show_id` は重ならないように、`sort_order` で並び順を指定）。

- 追加後、画面の **↻** で反映されます。
- `song_id` / `show_id` は一度使ったら変えない・使い回さない（披露記録がずれるため）。
- 曲名が `1/2` のように日付や数値と解釈されそうな場合は、セルの書式を **表示形式 → 数字 → 書式なしテキスト** にしてから入力してください（`setupSheets` で作ったシートは最初からテキスト書式です）。
- 楽曲を削除・統合するときも、披露記録（`performed_show_ids`）を確認してから行ってください。

## 同時編集への対策

更新はすべてサーバー側で `LockService` のロックを取り、**ロック取得後にシートの最新値を読み直して、対象の公演 ID だけを追加・削除**します。
A さんが東京、B さんが愛知を同時にチェックしても両方残ります。ロックが 10 秒取れない場合は保存せずエラーを返します。

## 開発

Node.js 18 以上があれば、追加インストールなしで動きます。

```sh
npm test          # Code.gs と表示ロジックのテスト（計画書の T01〜T14 を含む）
npm run preview   # http://localhost:8765/preview.html で画面を確認
npm run bundle    # 手で貼る用の dist/gas/Code.gs と dist/gas/Index.html を生成
```

プレビューは Code.gs をブラウザ内のモックで動かすもので、データはリロードで初期化されます。
`?fail=1` で保存失敗、`?delay=2000` で遅い通信を再現できます。

テスト T15（スマホでの閲覧・操作）は、実機またはブラウザのモバイル表示で確認してください。
